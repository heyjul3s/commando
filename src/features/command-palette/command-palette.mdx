# Command palette

The command palette brings query input and grouped results into one modal
surface. It uses the fixed `COMMANDS` catalogue from `src/shared/constants` and
coordinates a choice with the workspace-preview store.

## Composition

```text
CommandPalette
├── useCommandPalette
│   ├── useCommandPaletteLifecycle
│   └── useCommandPaletteKeyboard
├── SearchBar
│   └── useSearchBar

    └── useAvailableCommands
```

`setQuery` updates query and resets the active index together. Setting the same
query leaves the state unchanged. `closeCommandPalette` is the named store action
used for dismissal; it changes open state, while lifecycle cleanup remains in React.
Palette state is not persisted.

To choose a command, the list updates the workspace store's selection/history
and then closes the palette. Highlighting a row alone does neither. These command
labels are demo choices, not integrations that actually open projects, navigate,
or perform external actions.

## Filtering and display order

The utility trims and lowercases the query, then searches each command's label
and group. An empty query includes the whole catalogue. Groups follow first-match
order, and commands retain their order within each group. The flattened result
uses that same group order so index-based behaviour can match the rendered list.

## Integration

`CommandPalette` takes no props. Its hook consumers require both feature providers:

```tsx
import { AppProviders } from './app/providers';
import { CommandPalette } from './features/command-palette';

export function Example() {
  return (
    <AppProviders>
      <CommandPalette />
    </AppProviders>
  );
}
```

This alone starts closed. A trigger must call the palette store's
`setIsOpen(true)`. The workspace header supplies that trigger in the app, and
`useCommandPaletteShortcut` registers the global shortcut from beneath the providers.
`App` already owns `AppProviders`; do not wrap it again solely to make its stores available.

Storybook's preview supplies `AppProviders` globally. For a standalone open-palette
story, add a nearer `CommandPaletteProvider` with `initialValues={{ isOpen: true }}`.
Initial values initialise a store once; changing provider props is not a controlled
state update. Remount the provider or invoke an action for a new scenario.

## Surface and theme

The palette shell paints `--color-surface-raised` and the backdrop uses
`--color-overlay`. The command list deliberately leaves most row backgrounds
transparent. Give isolated list stories the same surface before assessing
contrast; a theme supplies token values but does not supply that container.

## Current interaction boundaries

Pointer selection, query filtering, close controls, and lifecycle reset are
implemented. Arrow-key navigation and Enter selection are handled on the search
input, while the palette keyboard hook handles Escape. `focus-trap-react` contains
focus within the dialog and restores the previously focused element on close
when it remains available. The application makes the workspace `inert` while
the palette is open; standalone integrations must manage their own background. The
[interaction guide](?path=/docs/documentation-interaction--docs) and
[accessibility guide](?path=/docs/documentation-accessibility--docs) distinguish the
current behaviour from the intended keyboard model.
