# Accessibility

Storybook's accessibility panel is one part of review. It can identify many
markup and contrast problems, but a clean automated result does not establish
complete keyboard or screen-reader support.

The [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
describes contained tab navigation and appropriate focus restoration. Declaring
`aria-modal="true"` does not implement either behaviour.

## Contrast review

For WCAG AA, ordinary text needs at least 4.5:1 contrast; qualifying large text
needs at least 3:1. Review the actual text size and weight before applying the
large-text exception. [Text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

Visual information needed to identify controls and their states generally needs
3:1 contrast against adjacent colours, subject to the criterion's exceptions.
This does not mean every decorative border or background needs that ratio.
[Non-text contrast guidance](https://www.w3.org/WAI/WCAG22/understanding/non-text-contrast.html)

Check default, hovered, highlighted, and focused appearances in both supported
token themes. Test each foreground/background pairing in context; a token is not
inherently accessible independently of its usage.

## When contrast is inconclusive

Expand the finding and inspect the affected nodes and explanation. An
inconclusive result means a calculation needs review; it is not a pass or a
confirmed failure.

For the standalone command list, first reproduce its production raised surface.
The list's rows are mostly transparent, so the surrounding background matters.
Then inspect clipped text, overlays, transparency, and any backgrounds the tool
cannot determine. Axe documents several such cases in its
[colour-contrast diagnostics](https://github.com/dequelabs/axe-core/blob/develop/lib/checks/color/color-contrast.json).

Keep the contrast rule enabled. Manually verify unresolved pairs and record the
result rather than changing production colours solely to silence a tool.

## Current implementation boundaries

- The search input is a named combobox and receives focus when it mounts. The assembled dialog also configures it as the focus trap's initial target.
- Close and history-clearing controls have visible or visually hidden labels. Clear search returns focus to the input.
- `FocusTrap` from `focus-trap-react` contains Tab and Shift+Tab navigation within the dialog and restores the previously focused element when the dialog unmounts, provided that element is still available to receive focus.
- The application sets `inert` on the workspace while the palette is open. This is owned by `AppContent`, so standalone palette integrations must manage their own background inertness.
- Command rows expose `role="option"`, stable IDs, and `aria-selected` inside a named listbox. Rows are excluded from the Tab order.
- The combobox uses `aria-controls` to reference the result list and `aria-activedescendant` to identify the highlighted option while focus stays in the input. `aria-expanded` reflects whether results are present.
- ArrowUp and ArrowDown wrap through filtered results; Enter selects the highlighted command and closes the palette. Hover updates the same highlight and active-descendant association.
- With no matches, the list is replaced by a “No commands found” status. The input reports `aria-expanded="false"` and omits `aria-controls` and `aria-activedescendant`; Enter leaves the palette open.
- Search navigation and palette Escape handling ignore already-handled events and IME composition. Escape dismissal belongs to the palette hook; the focus trap has `escapeDeactivates: false`.

These are implementation observations, not a conformance statement. Use the
assembled palette for manual focus and assistive-technology review.

## Automated and manual checks

The preview sets `a11y.test` to `error`. Resolve confirmed violations in the
component or its realistic story environment. Interaction assertions should
cover user-visible transitions; manual review should cover focus order,
announcements, composition, and visual clarity that the assertions do not capture.
