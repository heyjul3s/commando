# Design tokens

`src/styles.css` is the current source of truth. It defines light-mode values on
`:root` and `[data-theme='light']`, with dark-mode overrides beneath `[data-theme='dark']`. Values use CSS LCH;
components consume them through custom properties rather than copying colour values.

## Apply a theme and a surface

```tsx
<div
  data-theme="dark"
  style={{
    background: 'var(--color-surface-raised)',
    color: 'var(--color-text-primary)',
  }}
>
  <AvailableCommands />
</div>
```

The attribute changes inherited token values. The explicit background supplies
an actual surface. `color-scheme` helps native controls render appropriately;
it does not paint the component's container.

In the application, the command palette supplies `--color-surface-raised` around
the list. A standalone list story should reproduce that surface. Storybook's
manager theme changes its surrounding interface, not these application tokens.

For a global theme switch, apply the attribute to the preview document or a
wrapper containing every themed surface. A dark child overrides its inherited
variables; removing that attribute restores inherited values. A nested
`data-theme="light"` explicitly restores the light tokens beneath a dark ancestor.

## Extending the token set

Use a semantic token when an existing role fits. Add new roles with both theme
values and examples of their intended pairings. Keep theme overrides together in
`styles.css`. Spacing, typography, and radii remain component CSS values today;
this page does not imply those scales are already tokenized.
