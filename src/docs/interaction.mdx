# Interaction

The interface distinguishes a command being **highlighted** from one being
**chosen**. This distinction matters when reading both the workspace and the
interaction stories.

## Current flows

1. The workspace header opens the palette. The application also registers
   Command+K and Control+K to toggle its open state.
2. Mounting the search bar schedules focus on its input. Typing updates the shared
   query and resets the active index to zero when the query changes.
3. The list filters labels and group names, then groups the matches. Matching
   ignores case and surrounding whitespace.
4. Hover changes the highlighted index. It does not change the workspace's selected command.
5. Clicking a command updates workspace selection and recent history, then calls
   the palette's `closeCommandPalette` action.
6. The mounted palette lifecycle hook clears query and resets highlighting after
   the palette closes. The close store action itself changes only open state.

Clearing recent history leaves the selected command visible. Closing the palette
does not clear the workspace or its history.

Search navigation runs on the input; the palette keyboard hook handles Escape.
Both ignore already-handled events and IME composition so confirmation and
candidate-navigation keys remain available to the input method. On close, the
focus trap restores the previously focused element when it remains available.

## What belongs in a story

A visual state story establishes initial state without requiring a workflow.
An interaction story explains one transition, performs it, and asserts an
observable result. The Hover story reports the highlighted command; the Select
story reports workspace selection and whether the palette closed.

Use named play functions when the workflow would obscure the story declaration.
Keep reusable fixture data and provider setup beside the stories. Give each story
fresh stores and control persistence when testing a precise history scenario.

## Review the whole flow

Check pointer and keyboard routes separately. A window-dispatched key test cannot
prove that a focused button retains its native behaviour. Review focus location,
composition input, empty results, repeated activation, and close/reopen behaviour
in the assembled palette as well as isolated component stories.
